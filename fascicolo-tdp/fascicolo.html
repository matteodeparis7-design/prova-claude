Laboratorio: come si impara a programmare in C

Programmare si impara programmando, come si impara a nuotare in acqua. Leggere il fascicolo serve a capire; ma all'esame dovrai scrivere codice C corretto, su carta, da solo. Questo capitolo ti dice come allenarti, e alla fine del fascicolo trovi la Palestra di programmazione con 25 esercizi graduati e risolti.

1. Prepara l'ambiente

Al corso si usa Dev-C++ (Windows), un ambiente gratuito con editor, compilatore e debugger.

  1. Scarica Embarcadero Dev-C++ (la versione aggiornata) dal sito ufficiale e installalo.
  2. Imposta lo standard ANSI C, come chiede il professore: menu Strumenti → Opzioni di compilazione → Compilatore → Generazione di codice → Compilatore C → "Supporto programmi ANSI standard C" = Yes (in inglese: Tools → Compiler Options → Settings → C Compiler → Support all ANSI Standard C Programs).
  3. Per ogni esercizio: File → Nuovo → File sorgente, salva con estensione .c (non .cpp!), poi F11 (compila ed esegui).

Alternative: su Mac o Linux il compilatore gcc dal terminale (gcc -std=c89 -pedantic -Wall prova.c -o prova e poi ./prova); da telefono o da un PC qualsiasi, un compilatore online come OnlineGDB (scegli il linguaggio C).

Se la finestra si chiude subito

In alcune versioni di Dev-C++ la finestra del programma si chiude appena finisce. Esegui dal menu Esegui (che di solito aspetta un tasto) oppure aggiungi prima di return 0; le righe printf("premi invio"); getchar(); getchar();.

C, non C++

Il corso usa il linguaggio C (standard ANSI), non il C++, anche se l'ambiente si chiama "Dev-C++". In C++ si possono scrivere cose che in C non esistono: se le scrivi all'esame sono errori. Quindi:

NON usare (è C++) Usa invece (C)
#include <iostream>, cout << x, cin >> x #include <stdio.h>, printf, scanf
string s; (tipo stringa del C++) char s[N]; o char *s con malloc
new e delete malloc e free (#include <stdlib.h>)
bool, true, false int con 0 (falso) e 1 (vero)
parametri riferimento void f(int &x) puntatori: void f(int *x), chiamata f(&x)
using namespace std; non serve nulla
commenti // ... (non sono ANSI C89) commenti /* ... */
for (int i = 0; ...) (dichiarazione nel for) int i; all'inizio del blocco, poi for (i = 0; ...)
file salvato come .cpp file salvato come .c

Tutto il codice di questo fascicolo è C: l'ho compilato con le opzioni più severe del C ANSI (gcc -std=c89 -pedantic). Non confondere i due linguaggi neanche negli esempi che trovi online: molti "esercizi di C" sul web sono in realtà C++.

2. Il ciclo di lavoro: scrivi, compila, esegui, prova

Regola d'oro: compila spesso. Scrivi poche righe, compila, prova. Scrivere 100 righe e compilare alla fine produce 30 errori insieme e nessuna idea di dove cercarli.

3. Leggere gli errori del compilatore

Il compilatore ti dice file:riga e un messaggio (in inglese). Correggi sempre il primo errore: spesso gli altri sono conseguenze del primo. L'errore può essere sulla riga prima di quella indicata (tipicamente un ; mancante).

Messaggio (gcc / Dev-C++) Cosa vuol dire di solito
expected ';' before ... manca il punto e virgola alla fine della riga precedente
'x' undeclared variabile non dichiarata, o scritta in modo diverso (il C distingue maiuscole e minuscole: Somma ≠ somma)
implicit declaration of function 'f' funzione usata prima del suo prototipo, o #include mancante (es. string.h per strlen)
expected declaration or statement at end of input manca una } di chiusura
incompatible types / makes pointer from integer tipi sbagliati: ad esempio un int dove serve un puntatore, o dimenticato * o &
too few arguments to function chiamata con meno parametri del prototipo
format '%d' expects argument of type 'int *' (warning) in scanf manca la &
control reaches end of non-void function (warning) in qualche caso la funzione non arriva a un return

Gli avvisi (warning) contano: il programma compila, ma quasi sempre c'è un errore. Trattali come errori.

4. Quando il programma compila ma sbaglia: debugging

  1. Esecuzione simulata a mano: prendi carta e penna e segui il codice riga per riga con i dati del test che fallisce, scrivendo i valori delle variabili in una tabella (capitolo 4).
  2. Metodo delle stampe: aggiungi printf temporanee per vedere i valori, ad esempio printf("DEBUG i=%d somma=%d\n", i, somma); dentro il ciclo sospetto.
  3. Debugger di Dev-C++: metti un breakpoint (clic sul numero di riga), avvia con Debug, esegui passo passo e aggiungi le variabili da osservare (watch). Sulla pagina del corso c'è un video di esempio.

Gli errori a tempo di esecuzione più comuni:

  • il programma si blocca e va in crash: puntatore NULL o non inizializzato dereferenziato, indice fuori dall'array, scanf senza &;
  • il programma non termina: ciclo infinito (manca l'avanzamento, condizione sbagliata);
  • risultati strani: variabile non inizializzata, divisione intera, = al posto di ==.

5. Un metodo per risolvere qualunque esercizio

È lo stesso metodo che il professore applica a lezione e nelle EG:

  1. Capisci il problema: quali sono i dati di INPUT? Quale OUTPUT si vuole? Fai un esempio a mano con numeri piccoli.
  2. Scrivi l'algoritmo in italiano a passi numerati (pseudocodice, capitolo 3). Cerca gli schemi che conosci: contatore, accumulatore, massimo, ricerca con flag, scansione di lista...
  3. Scegli le strutture dati: variabili semplici? Un array? Una struct? Una lista?
  4. Dividi in funzioni: ogni sottoproblema una funzione; scrivi prima il main con le chiamate, poi i prototipi.
  5. Traduci in C un pezzo alla volta, compilando spesso; nei commenti indica il passo dell'algoritmo.
  6. Prova con casi scelti con criterio (capitolo 13): caso normale, casi limite (zero elementi, un elemento), dati "strani".

Capitolo 1

Il sistema di elaborazione

(slide lezioni 1-3 e "Cenni sul linguaggio macchina"; testo1 cap. 1, 2, 4.1-4.4)

Prima di programmare bisogna sapere che cosa esegue i programmi. Questo capitolo è teoria che può uscire all'orale.

La macchina di Von Neumann

Quasi tutti i calcolatori seguono lo schema di Von Neumann: i dati e il programma stanno nella stessa memoria, e una CPU esegue le istruzioni una dopo l'altra.

  • CPU (Central Processing Unit), il "cervello":
  • CU (Control Unit): legge le istruzioni, le decodifica e comanda le altre parti;
  • ALU (Arithmetic Logic Unit): fa i calcoli (somme, confronti, operazioni logiche);
  • registri: piccole memorie velocissime dentro la CPU. I più importanti: PC (Program Counter: contiene l'indirizzo della prossima istruzione) e IR (Instruction Register: contiene l'istruzione in esecuzione).
  • Memoria centrale (RAM): una lunga sequenza di locazioni, ognuna con un indirizzo (un numero). È volatile: si svuota quando spegni.
  • Memoria di massa (disco, SSD): lenta ma permanente; contiene i file.
  • Periferiche: input (tastiera, mouse), output (video, stampante).
  • Bus: i "fili" che collegano tutto (trasportano dati, indirizzi e segnali di controllo).

Il ciclo Fetch - Decode - Execute

La CPU ripete all'infinito tre passi:

  1. Fetch (prelievo): legge dalla RAM l'istruzione all'indirizzo scritto nel PC e la copia in IR; poi il PC viene fatto avanzare all'istruzione successiva.
  2. Decode (decodifica): la CU capisce che istruzione è (dal suo codice operativo) e attiva il circuito giusto.
  3. Execute (esecuzione): l'istruzione viene eseguita (un calcolo nella ALU, un trasferimento RAM-registro, un salto...).

Un salto (jump) non fa altro che scrivere un nuovo indirizzo nel PC: così la prossima istruzione prelevata non è quella "dopo", ma quella indicata.

Il linguaggio macchina del corso

A lezione si usa una macchina semplificata con una dozzina di istruzioni. Ogni istruzione è una parola di 32 bit: 8 bit di codice operativo, poi gli operandi.

Istruzione Codice Formato Cosa fa
LOAD 00000000 codice, registro (4 bit), indirizzo (20 bit) copia nel registro il contenuto della locazione
STORE 00000001 codice, registro, indirizzo copia nella locazione il contenuto del registro
ADD 00000010 codice, Ri, Rj Ri = Ri + Rj
SUB 00000100 codice, Ri, Rj Ri = Ri - Rj
MULT 00000110 codice, Ri, Rj Ri = Ri * Rj
DIV 00001000 codice, Ri, Rj Ri = Ri / Rj
MOD 00001010 codice, Ri, Rj resto della divisione
READ 00010000 codice, unità (4 bit), indirizzo legge un dato da input nella locazione
WRITE 00010001 codice, unità, indirizzo manda in output il dato della locazione
COMP 00100000 codice, Ri, Rj in RC: -1 se RiRj
JMP (salto condizionato) 00100001 codice, Ri, Rj, indirizzo se Ri == Rj mette l'indirizzo nel PC
STOP 10000001 codice termina il programma

Esempio della lezione: sommare le parole di indirizzo 64 e 68 e mettere il risultato all'indirizzo 60.

Per eseguirlo ("RUN") si mette nel PC l'indirizzo della prima istruzione; da lì parte il ciclo fetch-decode-execute.

Il software di base

Il calcolatore si può vedere a livelli (macchine "virtuali" una sopra l'altra): hardware, poi linguaggio macchina, poi sistema operativo, poi i linguaggi ad alto livello e le applicazioni. Ogni livello offre delle funzionalità a quello superiore e le realizza usando quelle del livello sottostante. Per questo chi programma in C non deve sapere come funzionano i circuiti.

  • Software di base: il sistema operativo e i programmi che servono a far funzionare e programmare la macchina (compilatori, linker, editor).
  • Software applicativo: i programmi per l'utente (browser, videogiochi, il tuo programma dei voli). Per usare le risorse (memoria, file, video) chiede i servizi al software di base.

  • Un programma è un testo (un file); un processo è un programma in esecuzione, con la sua memoria e il suo stato. Lo stesso programma lanciato due volte dà due processi.

  • Sistema operativo (SO): il programma che gestisce la macchina e la mette a disposizione degli altri programmi: gestisce i processi (programmi in esecuzione), la memoria, le periferiche e il file system.

  • File system: organizza i dati della memoria di massa in file e cartelle (directory) in una struttura ad albero. Un file si identifica con il suo percorso (es. C:\esercizi\voli.c).

Dal programma C al programma eseguibile

Il processore capisce solo il linguaggio macchina. Un programma scritto in un linguaggio ad alto livello come il C va tradotto:

  • Il preprocessore gestisce le righe che iniziano con # (#include <stdio.h>, #define N 10).
  • Il compilatore controlla il programma e lo traduce. Se trova errori non produce l'eseguibile.
  • Il linker collega il tuo codice con quello delle librerie (ad esempio il codice di printf).
  • Un IDE come Dev-C++ (usato al corso) fa tutto con un clic e include un debugger.

Nella memoria ci sono solo bit (0 e 1). Questo capitolo spiega come con i bit si rappresentano numeri interi, negativi e reali. Il floating point è uscito come esercizio 3 in un testo d'esame: va saputo fare a mano, senza errori.

Numeri e numerali

Un numero è un concetto; un numerale è la scrittura che lo rappresenta. Il numero dodici si scrive 12 in decimale, XII in cifre romane, 1100 in binario, C in esadecimale.

Nei sistemi posizionali ogni cifra "pesa" a seconda della posizione. In base b, il numerale cn-1...c1c0 vale:

cn-1·bn-1 + ... + c1·b1 + c0·b0

Base Cifre Esempio
2 (binario) 0, 1 10011100₂ = 128+16+8+4 = 156
8 (ottale) 0...7 234₈ = 2·64+3·8+4 = 156
10 (decimale) 0...9 156
16 (esadecimale) 0...9, A...F 9C₁₆ = 9·16+12 = 156

Conversioni

Da base 10 a base 2 (parte intera): divisioni successive

Dividi per 2, scrivi il resto, continua col quoziente finché arrivi a 0. Il numero binario sono i resti letti dal basso verso l'alto.

Da base 2 a base 10: somma dei pesi

10011100₂: i pesi delle cifre 1 sono 128, 16, 8, 4, quindi 128 + 16 + 8 + 4 = 156.

Base 2, 8 e 16: a gruppi di bit

  • in ottale, raggruppa i bit a 3 a 3 partendo da destra: 10 011 100 = 2 3 4₈;
  • in esadecimale, raggruppa i bit a 4 a 4: 1001 1100 = 9 C₁₆.

Parte frazionaria: moltiplicazioni successive

Moltiplica la parte frazionaria per 2: la parte intera del risultato (0 o 1) è la prossima cifra; continua con la nuova parte frazionaria. Si legge dall'alto verso il basso.

Molti numeri decimali "semplici" in binario sono periodici (infiniti): 0.1 = 0.000110011001100... Per questo float e double rappresentano molti reali solo in modo approssimato.

Interi senza segno: binario puro

Con n bit si hanno 2n numerali, quindi si rappresentano i numeri da 0 a 2n - 1 (con 8 bit: da 0 a 255).

Somma binaria: come in decimale, con i riporti. 0+0=0, 0+1=1, 1+1=0 con riporto 1, 1+1+1=1 con riporto 1.

Se il risultato non sta negli n bit si ha overflow.

Sottrazione binaria (con il "prestito", come in decimale): 0-0=0, 1-0=1, 1-1=0, 0-1=1 con prestito di 1 dalla cifra a sinistra.

Nei calcolatori però non si sottrae così: si somma il complemento a due del sottraendo (vedi sotto), così basta un solo circuito.

Quanti bit servono al minimo? Per un numero N ≥ 0 in binario puro serve il più piccolo n tale che 2n > N, cioè 2n - 1 ≥ N. Esempi: 121 < 128 = 27, quindi 7 bit; 591 < 1024 = 210 (e 591 > 511), quindi 10 bit; 256 = 28 richiede 9 bit (con 8 si arriva solo a 255). In complemento a due bisogna che il numero stia in [-2n-1, 2n-1-1]: per 121 servono 8 bit, per -591 ne servono 11.

Interi con segno

Modulo e segno

Il primo bit è il segno (0 = +, 1 = -), gli altri n-1 bit sono il valore assoluto. Intervallo: [-(2n-1-1), 2n-1-1]. Difetti: due zeri (000 e 100 con 3 bit) e circuiti più complicati per i calcoli. Per questo non si usa.

Complemento a due (quello vero)

Con n bit:

  • se V ≥ 0: la rappresentazione è il binario puro di V su n bit;
  • se V < 0: la rappresentazione è il binario puro di 2n + V (cioè 2n - |V|).

Intervallo rappresentabile: [-2n-1, 2n-1 - 1]. Con 8 bit: da -128 a +127. C'è un solo zero. Il primo bit vale 1 per tutti i negativi.

Metodo pratico per un negativo: scrivi |V| in binario su n bit, inverti tutti i bit (complemento a uno), aggiungi 1.

Estensione del segno: per scrivere lo stesso numero con più bit, si ripete a sinistra il primo bit. -1 è 111 su 3 bit, 1111 su 4, 11111111 su 8.

Sottrazione = somma del negativo: N - M = N + (-M), si sommano le rappresentazioni e si scarta l'eventuale riporto oltre l'ultimo bit.

Overflow in complemento a due: sommando due positivi si ottiene un "negativo" (o viceversa). Su 8 bit: 120 + 10 = 130, che non sta in [-128, 127]: 01111000 + 00001010 = 10000010, che si legge -126.

Numeri reali: il floating point a 32 bit

Viene dalla notazione scientifica: 223365000 = 2.23365 × 108, con una mantissa (le cifre) e un esponente (l'ordine di grandezza). In binario si normalizza la mantissa nella forma 1.xxxx.

Il float occupa 32 bit:

Il numero rappresentato è: (-1)s × 1.M × 2E - 127

  • s: 0 positivo, 1 negativo;
  • E: l'esponente vero più 127 (si dice "in eccesso 127"). Così E va da 0 a 255 e l'esponente vero può essere negativo;
  • M: le cifre dopo la virgola della mantissa normalizzata, completate con zeri a destra fino a 23 bit.

Procedura in 5 passi (da usare all'esame)

  1. Segno: s = 0 se positivo, 1 se negativo. Da qui lavora col valore assoluto.
  2. Converti in binario parte intera (divisioni) e parte frazionaria (moltiplicazioni).
  3. Normalizza: sposta la virgola subito dopo il primo 1. Conta di quante posizioni l'hai spostata: è l'esponente e (positivo se l'hai spostata a sinistra, negativo se a destra).
  4. Esponente: E = e + 127, scritto in binario su 8 bit.
  5. Mantissa: M = le cifre dopo "1.", portate a 23 bit (zeri a destra se mancano; se avanzano, si troncano).

Esempio: 4.25 (dalle slide)

4.25 = 100.01₂ → normalizzato 1.0001 × 22 → E = 2 + 127 = 129 = 10000001, M = 0001.

Esempio: 796.25 (dalle slide)

796 = 1100011100, 0.25 = .01 → 1100011100.01 = 1.10001110001 × 29. E = 9 + 127 = 136 = 10001000; M = 10001110001 + zeri.

Esempio inverso: da bit a numero

1 10000000 10010010000000000000000: s = 1 (negativo); E = 128, quindi e = 128 - 127 = 1; mantissa = 1.1001001 = 1 + 1/2 + 1/16 + 1/128 = 1.5703125. Numero = -1.5703125 × 21 = -3.140625.

Algoritmo e programma

Un algoritmo è una sequenza finita di passi precisi (non ambigui) che risolve un problema in un tempo finito. Un programma è un algoritmo scritto in un linguaggio di programmazione. Prima si pensa l'algoritmo (anche con un diagramma a blocchi o in italiano), poi lo si traduce in C.

La programmazione strutturata (teorema di Böhm-Jacopini) dice che ogni algoritmo si può scrivere usando solo tre strutture: sequenza, selezione (if) e iterazione (while). Niente salti goto.

Scrivere un algoritmo: pseudocodice e diagrammi di flusso

A lezione gli algoritmi si scrivono prima in pseudocodice: passi numerati, in italiano, con INPUT(...) per leggere i dati e OUTPUT(...) per comunicare i risultati. Solo dopo si traduce in C, e nel codice si indica con un commento quale istruzione realizza quale passo.

Esempio (lezione 3): massimo comun divisore di due interi positivi n e m. Idea: il MCD non può essere più grande del minore dei due; parto da lì e scendo finché trovo un numero che divide entrambi (al limite arrivo a 1, che divide tutto, quindi il ciclo termina sempre).

Nota la condizione del passo 3: "continua finché ris non divide entrambi" è la negazione di "ris divide n e divide m", e per De Morgan diventa un OR (vedi più avanti).

Variabili e tipi semplici

Una variabile ha quattro aspetti, come insiste il professore: un identificatore (il nome), una locazione di memoria con il suo indirizzo, un tipo e un valore (il contenuto della locazione). Leggere una variabile (usarla in un'espressione) non ne cambia il valore; scriverla (assegnamento, scanf) sostituisce il vecchio valore, che va perso. Il tipo dice quanti byte occupa e come interpretare i bit.

Algebra di Boole ed espressioni logiche

In C 0 è falso e qualunque valore diverso da 0 è vero.

a b a && b a || b !a
0 0 0 0 1
0 1 0 1 1
1 0 0 1 0

Leggi di De Morgan (servono per negare le condizioni dei cicli):

  • !(a && b) equivale a !a || !b
  • !(a || b) equivale a !a && !b

Esempio: il contrario di "x è tra 1 e 10" (x >= 1 && x <= 10) è (x < 1 || x > 10).

Funzioni e record di attivazione

(slide lezioni 8 e 10, complemento "Record di attivazione"; testo1 cap. 11)

Perché le funzioni

Una funzione è un sottoprogramma con un nome, che risolve un sottoproblema. Serve a non ripetere codice, a dividere un problema grande in pezzi (modularizzazione, progettazione top-down) e a provare ogni pezzo separatamente.

Dichiarazione, definizione, chiamata

  • Prototipo: tipo restituito, nome, tipi dei parametri. Permette al compilatore di controllare le chiamate.
  • Definizione: intestazione + corpo. n e m sono i parametri formali.
  • Chiamata: i parametri attuali sono espressioni: il loro valore viene copiato nei parametri formali.
  • return espressione; termina la funzione e restituisce il valore al chiamante. Una funzione void non restituisce nulla.

Passaggio dei parametri per valore

In C i parametri passano sempre per valore: la funzione riceve una copia. Modificare un parametro formale non cambia la variabile del chiamante.

scambioNO(a, b) scambia solo le copie: dopo la chiamata a e b sono uguali a prima. Per modificare una variabile del chiamante bisogna passarne l'indirizzo (scambio(&a, &b)): lo vedremo bene con i puntatori (capitolo 8). È il meccanismo dei parametri di output, che userai in ogni esercizio 1 d'esame.

Il record di attivazione (RDA)

Ogni volta che una funzione viene chiamata succede questo:

  1. l'esecuzione del chiamante si sospende;
  2. viene allocata in memoria (sulla pila, stack) una zona chiamata record di attivazione (RDA). Contiene: - i parametri formali, riempiti con le copie dei valori dei parametri attuali; - le variabili locali; - il valore di ritorno e l'indirizzo di ritorno (dove riprendere nel chiamante);
  3. si esegue il corpo della funzione, usando le locazioni del suo RDA;
  4. con return il valore torna al chiamante, l'RDA viene deallocato (sparisce) e il chiamante riprende.

Le RDA si impilano: se main chiama f e f chiama g, sulla pila ci sono main, f, g; quando g finisce si torna a f. Questa pila diventa fondamentale per capire la ricorsione (capitolo 11).

Visibilità e ciclo di vita delle variabili

  • Variabili locali (dichiarate in una funzione o in un blocco): visibili solo lì; nascono quando la funzione viene attivata e muoiono quando termina (vivono nell'RDA). Due funzioni possono avere variabili locali con lo stesso nome: sono variabili diverse.
  • Variabili globali (dichiarate fuori da ogni funzione): visibili in tutte le funzioni dopo la dichiarazione; vivono per tutto il programma. Da usare il meno possibile (rendono difficile capire chi modifica cosa).
  • Variabili locali static: visibili solo nella funzione, ma conservano il valore tra una chiamata e l'altra.
  • Una variabile locale nasconde una globale con lo stesso nome (shadowing).

Restituire l'indirizzo di una variabile locale

Per restituire memoria che "sopravvive" alla funzione si usa malloc (capitolo 9).

Progettare con le funzioni (il metodo del corso)

  1. ambiente di calcolo: scrivo il main con le variabili e le chiamate delle funzioni che mi servono, come se esistessero già;

Che cos'è un array

Un array è una sequenza di N elementi dello stesso tipo, in locazioni consecutive di memoria, a cui si accede con un indice da 0 a N-1.

  • La dimensione deve essere una costante (in ANSI C), per questo si usa #define.
  • Gli array non si copiano con = e non si confrontano con ==: si lavora elemento per elemento con un ciclo.

Uscire dall'array

v[N] non esiste (l'ultimo è v[N-1]). Il C non controlla gli indici: scrivere fuori dall'array rovina altre variabili o fa andare in crash il programma, senza messaggi. Controlla sempre la condizione dei cicli: i < N, non i <= N.

Array e funzioni

Quando passi un array a una funzione, passi l'indirizzo del suo primo elemento (non una copia!). Conseguenze:

  • la funzione può modificare l'array originale;
  • la funzione non conosce la dimensione: va passata come parametro.

L'intestazione int massimo(int v[], int dim) è equivalente a int massimo(int *v, int dim) (capitolo 8).

Una funzione non può restituire due valori con return. Per minimo e massimo si usano parametri di output:

Si chiama così: minMax(v, N, &mn, &mx);

Array parzialmente riempito

Spesso non si sa quanti dati ci saranno. Si alloca un array "abbastanza grande" (il sostegno) e si tiene in una variabile quanti elementi sono davvero usati. Gli elementi validi sono sempre i primi, da 0 a quanti-1.

Questa è proprio l'idea della tabella (capitolo 10): un array di struct più un intero quanti.

Matrici (array a due dimensioni)

In memoria la matrice è memorizzata per righe, una riga dopo l'altra. Passandola a una funzione, il numero di colonne va scritto: void stampaMat(int m[][C], int righe).

File testuali e binari

(lezione 9 con video, EG7; testo1 cap. 17)

Le variabili vivono in RAM e spariscono a fine programma. Per conservare i dati servono i file, che stanno nella memoria di massa.

Aprire e chiudere un file

Modo Significato
"r" lettura; il file deve esistere
"w" scrittura; crea il file o lo svuota se esiste
"a" aggiunta in fondo (append)
"r+" lettura e scrittura di un file esistente
"rb", "wb", "ab"... come sopra, per file binari

File di testo: I/O formattato

Si usano come printf/scanf, ma con il file come primo argomento: fprintf(f, ...) e fscanf(f, ...).

Per leggere "fino alla fine" si usa il valore restituito da fscanf (quanti dati ha letto): quando i dati finiscono restituisce EOF (un valore negativo) o comunque un numero diverso da quelli richiesti.

feof

Esiste anche feof(f), che diventa vero dopo che una lettura ha provato a superare la fine. Il ciclo while (!feof(f)) { fscanf(...); ... } elabora l'ultimo dato due volte se il file finisce con un a capo. Il controllo sul valore di fscanf è più sicuro.

Altre funzioni utili: fgetc(f) / fputc(c, f) per un carattere alla volta; fgets(buffer, dim, f) per una riga intera.

Lo standard input e output sono anch'essi file già aperti: stdin, stdout. printf(...) equivale a fprintf(stdout, ...).

File binari

Un file di testo contiene caratteri (il numero 1216 occupa 4 caratteri). Un file binario contiene i byte così come sono in memoria (un int occupa sempre sizeof(int) byte). È più compatto e veloce, ma non si legge con un editor di testo.

  • fwrite(indirizzo, dimensione_elemento, quanti, f): scrive quanti elementi presi dall'indirizzo dato; restituisce quanti ne ha scritti.
  • fread(indirizzo, dimensione_elemento, quanti, f): legge fino a quanti elementi; restituisce quanti ne ha letti (0 alla fine del file).
  • fseek(f, spostamento, origine): sposta la posizione corrente (accesso diretto, random). Origine: SEEK_SET (inizio), SEEK_CUR (posizione attuale), SEEK_END (fine).
  • ftell(f): posizione corrente in byte; rewind(f): torna all'inizio.

Con un file binario di record tutti uguali si può leggere direttamente il k-esimo record, senza leggere quelli prima: è il vantaggio dell'accesso diretto.

Errori frequenti con i file

  • Non controllare se fopen ha restituito NULL.
  • Dimenticare fclose (i dati scritti possono restare nel buffer e andare persi).
  • Aprire con "w" un file che si voleva solo leggere: lo si svuota.
  • Salvare in un file binario una struct che contiene un puntatore (char *descrizione): si salva l'indirizzo, non la stringa! Al prossimo avvio quell'indirizzo non vale più nulla. Le stringhe esatte vanno salvate come testo, oppure scrivendo prima la lunghezza e poi i caratteri.

Capitolo 8

Puntatori

(slide lezioni 13 e 14, complementi lezione 13; testo1 cap. 14)

I puntatori sono l'argomento chiave del corso: senza di loro non si fanno né i parametri di output né le liste. Vale la pena studiarli con calma e con tanti disegni.

Indirizzi e puntatori

Ogni variabile occupa una locazione di memoria che ha un indirizzo. Un puntatore è una variabile che contiene un indirizzo.

  • & (indirizzo di): applicato a una variabile, dà il suo indirizzo.
  • * (dereferenziazione): applicato a un puntatore, dà la variabile puntata.
  • Nella dichiarazione int *p; l'asterisco dice solo che p è un puntatore.
  • NULL (definito in stdio.h e stdlib.h) è il puntatore che non punta a niente. Dereferenziare NULL fa andare in crash il programma.

Puntatore non inizializzato

int *p; *p = 3; scrive in un indirizzo casuale. Un puntatore va sempre inizializzato: a NULL, all'indirizzo di una variabile, o al risultato di malloc.

Parametri di output (passaggio per indirizzo)

Per permettere a una funzione di modificare una variabile del chiamante, le si passa l'indirizzo della variabile. La funzione lavora con *parametro.

È lo stesso meccanismo di scanf("%d", &x): scanf deve scrivere dentro x, quindi le serve il suo indirizzo.

Schema per gli esercizi d'esame ("la funzione restituisca A, B e C"): uno dei risultati con return, gli altri come parametri puntatore.

Parentesi con ++

Dentro la funzione, per incrementare un contatore di output scrivi (*conta)++;. Senza parentesi *conta++ incrementa il puntatore (precedenza di ++) e non il valore. In alternativa: *conta = *conta + 1;.

Puntatori e array

Il nome di un array è l'indirizzo del suo primo elemento: v equivale a &v[0].

Aritmetica dei puntatori: se p punta a un elemento di un array, p + 1 punta all'elemento successivo (il compilatore aggiunge sizeof(tipo) byte, non 1). Quindi:

Capitolo 9

Stringhe e allocazione dinamica della memoria

(slide lezioni 15 e 16, EG5, video "ArrayDouble"; testo1 cap. 13, 14, app. B)

Le stringhe in C

Una stringa è un array di char terminato dal carattere '\0' (codice 0). Il '\0' segna la fine: per questo una stringa di k caratteri occupa k+1 caratteri.

Lettura e stampa: scanf("%s", s); (senza &, perché s è già un indirizzo; legge fino al primo spazio) e printf("%s", s);. Per leggere una riga con spazi: fgets(s, 10, stdin); (che però tiene anche il '\n' finale).

Le funzioni di string.h

Funzione Cosa fa
strlen(s) numero di caratteri escluso il '\0'
strcpy(dest, src) copia src in dest (dest deve avere spazio!)
strncpy(dest, src, n) copia al massimo n caratteri (può non mettere il '\0')
strcmp(a, b) 0 se uguali, < 0 se a viene prima in ordine alfabetico, > 0 se dopo
strcat(dest, src) aggiunge src in fondo a dest

Le stringhe non si confrontano con == e non si copiano con =

if (s1 == s2) confronta gli indirizzi, non il contenuto: si usa strcmp(s1, s2) == 0. E s1 = s2; tra array non compila (oppure, tra puntatori, copia l'indirizzo e non i caratteri): si usa strcpy. Questo errore all'esame costa caro, perché i testi chiedono sempre di cercare per nome, codice o grado.

Allocazione statica e dinamica

  • Statica / automatica: la dimensione è decisa quando scrivi il programma (int v[100];). Le variabili locali vivono nell'RDA e muoiono con la funzione.
  • Dinamica: la memoria si chiede durante l'esecuzione, quando si sa quanta ne serve, in una zona chiamata heap. Rimane allocata finché non la liberi tu con free, anche dopo la fine della funzione che l'ha chiesta.

Funzioni di stdlib.h:

Funzione Cosa fa
malloc(nbyte) alloca nbyte byte e restituisce l'indirizzo (contenuto casuale), NULL se non c'è memoria
calloc(n, dim) alloca n elementi di dim byte e li azzera
realloc(p, nuovaDim) cambia la dimensione del blocco puntato da p (può spostarlo: usa l'indirizzo restituito)
free(p) restituisce al sistema il blocco puntato da p

I tre errori della memoria dinamica

  1. Non controllare NULL dopo malloc.
  2. Memory leak: perdere l'ultimo puntatore a un blocco senza averlo liberato (la memoria resta occupata fino alla fine del programma).
  3. Usare memoria già liberata (dangling pointer): dopo free(p), p contiene ancora il vecchio indirizzo ma la memoria non è più tua. Se serve, scrivi p = NULL; subito dopo.

Stringhe "esatte"

Una stringa esatta è allocata con esattamente lo spazio necessario: strlen + 1 caratteri. Nessuno spreco. È la tecnica richiesta in tutti i testi d'esame per i campi "stringa di lunghezza non nota a priori".

Duplicato esatto di una stringa

La memoria allocata con malloc sopravvive alla fine di duplicato: l'RDA sparisce (con la variabile nuova), ma il blocco resta, e il suo indirizzo è stato restituito al chiamante.

Lo schema con il buffer

Per leggere una stringa di lunghezza ignota:

  1. si legge in un buffer abbastanza grande (char buffer[LUNGMAX+1]);
  2. si alloca con malloc(strlen(buffer) + 1);
  3. si copia con strcpy;
  4. il buffer si riusa per la prossima lettura.

Struct: il record

Un array raccoglie dati dello stesso tipo. Una struct (record) raccoglie dati di tipi diversi che descrivono una cosa sola. Ogni componente si chiama campo.

Accesso ai campi con il punto:

A differenza degli array, le struct si possono assegnare con = (si copiano tutti i campi) e passare/restituire per valore. Non si possono però confrontare con ==.

Tabelle: array di struct

Una tabella è una struttura dati che rappresenta un archivio del mondo reale: una collezione di elementi dello stesso tipo (record). Le operazioni tipiche sono:

  • aggiunta di un elemento;
  • eliminazione di un elemento;
  • modifica dei dati di un elemento;
  • ricerca di un elemento tramite la sua chiave.

La chiave di ricerca è il campo che identifica un elemento in modo univoco (codice del volo, matricola, codice fiscale).

Capitolo 11

Ricorsione

(slide lezione 17, EG8, complementi lezione 8 sui record di attivazione; testo1 cap. 15)

L'idea

Una funzione è ricorsiva quando chiama se stessa. Funziona se:

  1. c'è almeno un caso base, che si risolve direttamente, senza chiamate ricorsive;
  2. il caso ricorsivo riduce il problema a uno dello stesso tipo ma più piccolo, e si avvicina sempre al caso base.

Il modo di pensare: "supponiamo che la funzione sappia già risolvere il problema più piccolo; come uso quel risultato per risolvere il problema grande?"

Il fattoriale

n! = n × (n-1) × ... × 1, e per definizione 0! = 1. Ma n! = n × (n-1)! : ecco la ricorsione.

Versione iterativa, per confronto:

Con int il fattoriale va in overflow già con n = 13 (13! supera 231-1); con long a 64 bit si arriva a 20.

Visualizzare la ricorsione con i record di attivazione

Ogni chiamata ricorsiva crea un nuovo RDA, con i suoi parametri e le sue variabili locali. Le RDA si impilano; quando si arriva al caso base, le chiamate terminano una alla volta in ordine inverso, ciascuna restituendo il valore alla precedente.

  2. Disegna una RDA per ogni chiamata, impilandole, con parametri, variabili locali e punto di ritorno ("aspetta il risultato di ...").
  3. Segna il caso base e il valore che restituisce.

Inversione dell'input (EG8)

Leggere caratteri fino al punto e stamparli al contrario (TOPI. → IPOT). L'idea: leggo un carattere; se non è il punto, faccio leggere e invertire il resto e poi stampo il carattere letto.

Ogni RDA conserva il suo ch: è la pila delle RDA a "ricordare" i caratteri, senza bisogno di un array.

Palindromi (EG8)

Una parola è palindroma (radar, anna, ingegni) se si legge uguale nei due sensi. La porzione p[i..j] è palindroma se p[i] == p[j] e la porzione interna p[i+1..j-1] è palindroma. Caso base: i >= j (zero o un carattere: palindroma).

Altri esempi

Ricorsione sulle liste

Una lista è vuota, oppure è un nodo seguito da una lista. Per questo le funzioni ricorsive sulle liste sono naturali: caso base l == NULL, caso ricorsivo "faccio qualcosa col primo nodo e chiamo la funzione su l->next". Le trovi nel capitolo 14.

Ricorsione o iterazione?

  • Tutto quello che si fa con la ricorsione si può fare con i cicli, e viceversa.
  • La ricorsione è spesso più semplice da scrivere e da capire quando il problema è ricorsivo per natura (liste, alberi, divide et impera).
  • Costa di più: ogni chiamata alloca un RDA (tempo e memoria). Con troppe chiamate annidate la pila si esaurisce (stack overflow).
  • Esempio da evitare: Fibonacci "ingenuo" fib(n) = fib(n-1) + fib(n-2) ricalcola gli stessi valori un numero esponenziale di volte.

Errori tipici

  • Manca il caso base, o il caso ricorsivo non si avvicina al caso base: ricorsione infinita, il programma va in crash.
  • Dimenticare return davanti alla chiamata ricorsiva: return 1 + conta(l->next); e non solo conta(l->next);.
  • Usare una variabile locale "per accumulare" tra le chiamate: ogni RDA ha la sua copia; il risultato si costruisce con i valori restituiti.

Capitolo 12

Ricerca e ordinamento

(slide lezione 20 e filmati sugli algoritmi di ordinamento; testo1 cap. 11, 12, caso di studio I; testo2 cap. 1-2)

Ricerca lineare (sequenziale)

Si scorre l'array dall'inizio finché si trova l'elemento o si arriva in fondo. Funziona sempre, anche se l'array non è ordinato. Nel caso peggiore fa n confronti.

Ricerca binaria (dicotomica)

Funziona solo su array ordinati. Si guarda l'elemento centrale: se è quello cercato, fatto; se il cercato è più piccolo si continua nella metà sinistra, altrimenti nella destra. A ogni passo si dimezza lo spazio di ricerca: al massimo circa log2 n confronti (per n = 1000, circa 10 invece di 1000).

Algoritmi di ordinamento

Ordinare = disporre gli elementi in ordine (di solito crescente). Esempio usato qui sotto: 29 10 14 37 13.

Selection sort (ordinamento per selezione)

A ogni passo seleziono il minimo della parte non ancora ordinata e lo scambio con il primo elemento di quella parte.

Bubble sort (ordinamento a bolle)

Scorro l'array confrontando coppie di elementi vicini e le scambio se sono in ordine sbagliato. Dopo ogni passata il più grande "sale come una bolla" in fondo. Mi fermo quando una passata non fa scambi.

Insertion sort (ordinamento per inserimento)

Come quando si ordinano le carte in mano: prendo un elemento alla volta e lo inserisco al posto giusto nella parte già ordinata a sinistra, spostando a destra quelli più grandi.

Merge sort (cenni)

Divide et impera, ricorsivo: divido l'array a metà, ordino ricorsivamente le due metà, poi le fondo (merge) in un'unica sequenza ordinata, confrontando ogni volta i primi elementi delle due metà.

Quanto costano (complessità, cenni)

L'efficienza di un algoritmo si misura con il numero di operazioni in funzione della dimensione n dei dati (nel caso peggiore).

Capitolo 13

Qualità dei programmi e test di correttezza

(lezione 12, solo online, con video; slide "Qualità e Testing"; testo2 cap. 1-2)

Questo argomento esce spesso come esercizio 3 ("descrivere il metodo a scatola nera / trasparente e applicarlo a eser1"). Vale fino a 7 punti e si prepara bene in anticipo.

Le qualità di un programma

  • Efficienza: quanto tempo impiega e quanto spazio (memoria) usa. Si gestisce studiando l'algoritmo e la sua complessità.
  • Robustezza: il programma funziona anche con usi anomali (input sbagliato, file mancante, memoria esaurita). Si gestisce controllando i dati in ingresso, chiedendo l'input in modo chiaro, controllando NULL dopo malloc e fopen.
  • Correttezza: il programma fa quello che ci si aspetta. Si verifica con i test.

Gli errori

Tipo Quando si scopre Esempio
lessicale compilazione returna x; (parola che non esiste)
sintattico compilazione foor (i=0; ...), ; mancante
semantico compilazione int i = 8.4; (tipi incompatibili), variabile non dichiarata
logico / di codifica solo con i test prod = prod + i invece di prod = prod * i; i <= i invece di i <= n

Il compilatore segnala un errore dopo averlo trovato: la riga sbagliata può essere prima di quella indicata.

Un programma che compila non è detto che sia corretto. Bisogna testarlo.

Che cos'è un test

Test = (1) eseguire il programma con certi dati di prova; (2) confrontare l'output atteso (calcolato a mano prima) con l'output effettivo. Se coincidono si passa al test successivo; se no si fa debugging: si ispeziona il codice, si aggiungono stampe delle variabili (metodo delle stampe), si usa il debugger (watch sulle variabili, esecuzione passo passo, call stack).

Test fatti a caso non bastano. L'esempio del professore:

Test Input Atteso Effettivo
1 (diverse) PERA, TRAM 0 0
2 (uguali) PERA, PERA 1 1
3 (diverse, ultima lettera uguale) PERA, MELA 0 1

I primi due test passano, eppure la funzione è sbagliata: conta solo l'ultimo confronto. Serve un metodo per scegliere i test prima di farli. I metodi sono due.

Metodo a scatola nera (copertura dell'input)

Si scelgono i test guardando solo la specifica (che cosa deve fare la funzione), senza guardare il codice.

  1. Si partiziona l'insieme dei possibili input in classi di equivalenza: input di una stessa classe dovrebbero essere trattati "allo stesso modo" (stesso tipo di output atteso).
  2. Si sceglie un rappresentante per classe: un test per ogni classe.
  3. Più le classi sono specifiche, più test si fanno e più si è sicuri. Bisogna considerare in particolare i casi limite: struttura vuota, un solo elemento, elemento cercato in prima / ultima posizione, assente, valori uguali alla soglia...

Esempio (lezione) per indiceVolo(TipoTabella t, char *codice): tabella vuota; tabella piena e codice presente; tabella piena e codice assente; codice presente in prima posizione; codice presente in ultima posizione; codice presente in mezzo...

Metodo a scatola trasparente (copertura del codice)

Si scelgono i test guardando il codice, in modo che, nel complesso, i test mettano in azione le sue parti. Ci sono criteri via via più scrupolosi:

  1. Copertura delle istruzioni: alla fine dei test ogni istruzione è stata eseguita almeno una volta.
  2. Copertura delle decisioni: in più, ogni decisione (condizione di if, while, for) è stata vera almeno una volta e falsa almeno una volta.
  3. Copertura delle condizioni: in più, ogni condizione elementare dentro una decisione composta (es. A<10 e C<20 in A<10 || C<20) è stata vera e falsa almeno una volta.
  4. Valori limite: si aggiungono test con i valori al limite delle condizioni (es. 0, 10, 20) e vicini al limite (9, 11, 19, 21, -1, +1).

Per i cicli, si prova anche: zero iterazioni, una iterazione, più iterazioni.

L'esempio della lezione: si voleva "se A ≠ 0 stampa 1; se A < 10 e C < 20 stampa 2", ma si è scritto if (A > 0) e if ((A < 10) || (C < 20)). Il test A=3, C=18 copre tutte le istruzioni ma non trova gli errori; aggiungendo criteri e valori limite (A=-3, A=0, C=20, A=20...) gli errori emergono. Nessun criterio garantisce di trovare tutti gli errori: più criteri = più test = più costo, ma più sicurezza.

Test top-down (per programmi con molte funzioni)

Si fa un test incrementale: si prova una funzione alla volta, partendo dal main. Le funzioni non ancora provate si sostituiscono con stub: versioni finte che restituiscono direttamente il risultato giusto per il test in corso. Se qualcosa va storto, l'errore può essere solo nella funzione che si sta provando.

Capitolo 14

Liste collegate

(slide lezioni 21-25, EG10 e EG11; testo2 cap. 6)

Il capitolo più importante

Gli esercizi 1 e 2 dello scritto (23 punti su 30) sono sempre sulle liste. Studia questo capitolo finché sai scrivere a memoria e senza errori tutte le funzioni qui sotto, disegnando i puntatori.

L'idea

Una lista collegata (o concatenata) è una sequenza di nodi. Ogni nodo è una struct allocata dinamicamente con:

  • l'informazione (info): un intero, o una struct con tutti i dati dell'elemento;
  • un puntatore al nodo successivo (next). L'ultimo nodo ha next == NULL.

La lista si identifica con il puntatore al primo nodo (la testa). La lista vuota è il puntatore NULL.

Rispetto all'array: la lista cresce e si accorcia un nodo alla volta (nessuna dimensione massima, nessuno spreco) e si inserisce/elimina senza spostare gli altri elementi; però per raggiungere il k-esimo elemento bisogna scorrere dall'inizio (niente accesso diretto v[k]).

I tipi

  • struct nodo contiene un puntatore a struct nodo: è una struttura ricorsiva (per questo serve il nome struct nodo e non basta il typedef, che non è ancora definito a quel punto).
  • TipoLista è un puntatore. Una variabile lista si dichiara e si inizializza sempre a NULL: TipoLista l = NULL;.

Nomi e convenzioni

Il libro Calvanese et al. usa nomi come TipoSCL (Sequenza Collegata Lineare) e TipoNodoSCL; a lezione si usano anche nomi come insTestaLista. I nomi non contano: conta la struttura. All'esame, se il testo chiede un nome (es. TipoReggimento), usa quello.

La funzione... Parametro Esempi

Dentro la funzione con TipoLista *pl, la testa è *pl. Per passarla a una funzione che legge soltanto: stampaLista(*pl).

Inserimento in coda

Bisogna arrivare all'ultimo nodo (quello con next == NULL) e attaccargli il nuovo. Caso speciale: se la lista è vuota, il nuovo nodo diventa la testa.

Attenzione alla condizione while (p->next != NULL): ci si ferma sull'ultimo nodo, non dopo (con while (p != NULL) si uscirebbe con p == NULL e non si saprebbe più a chi attaccare il nuovo nodo).

La tecnica del record generatore (RG)

Il caso speciale "lista vuota / primo nodo" esiste perché il primo nodo non ha un predecessore. Il record generatore è un nodo fittizio messo davanti alla lista: così ogni nodo vero ha un predecessore e il caso speciale sparisce. Alla fine la testa vera è rg.next.

Il RG è comodo in tutte le operazioni in cui serve il predecessore: inserimento in coda, inserimento ordinato, eliminazione (anche di più nodi, vedi capitolo 18).

Inserimento ordinato

Lista ordinata in modo crescente: bisogna trovare il primo nodo con info ≥ x e inserire il nuovo nodo prima di lui. Per inserire "prima" serve il nodo precedente: si scorre con due puntatori, prec e corr.

I casi da controllare: lista vuota (prec resta NULL: nuova testa), x più piccolo di tutti (prec == NULL: nuova testa), x più grande di tutti (corr == NULL: in coda), x in mezzo.

Per le stringhe la condizione diventa strcmp(corr->info.nome, nome) < 0.

Eliminazione di un elemento

Stessa tecnica dei due puntatori: si cerca il nodo da eliminare ricordando il precedente, poi lo si "scavalca" e si libera la memoria.

Errori tipici nelle eliminazioni

  • free(corr) prima di aver collegato prec->next = corr->next: dopo la free non si può più leggere corr->next.
  • Dimenticare il caso "elimino il primo nodo": va cambiata la testa (*pl = corr->next), quindi il parametro deve essere TipoLista *.
  • Se il nodo contiene stringhe esatte, liberarle prima del nodo: free(corr->info.nome); free(corr);. Altrimenti è un memory leak.

Deallocazione di tutta la lista

Bisogna salvare il nodo da liberare, avanzare, e poi liberare: dopo free non si può più seguire il suo next.

Definizione

Un albero binario è vuoto, oppure è formato da un nodo radice con due sottoalberi binari: il sinistro e il destro. È una definizione ricorsiva, come quella della lista.

Termini: radice (il nodo in cima), figli e padre, foglia (nodo senza figli), altezza (lunghezza del cammino più lungo dalla radice a una foglia: qui 3).

I tipi in C

Le tre visite (in profondità)

Visitare un albero significa esaminare tutti i suoi nodi. Le tre visite ricorsive differiscono solo per quando si esamina la radice:

  • preordine (anticipata): radice, poi sottoalbero sinistro, poi destro;
  • inordine (simmetrica): sinistro, radice, destro;
  • postordine (posticipata): sinistro, destro, radice.

Albero binario di ricerca (ABR)

Un ABR è un albero binario in cui, per ogni nodo, tutti i valori nel sottoalbero sinistro sono minori della sua info e quelli nel destro sono maggiori o uguali. Conseguenze: la visita inordine dà i valori ordinati; la ricerca scende a sinistra o a destra, come la ricerca binaria (su un albero bilanciato circa log2 n passi).

La deallocazione si fa in postordine: prima i figli, poi il nodo (dopo free non si potrebbero più raggiungere i figli).

Architettura e rappresentazione

Cos'è l'architettura di Von Neumann?

Uno schema di calcolatore in cui programma e dati stanno nella stessa memoria centrale; una CPU (unità di controllo, ALU, registri) preleva ed esegue le istruzioni una alla volta; memoria e periferiche sono collegate da un bus.

Cosa fanno PC e IR? Cos'è il ciclo fetch-decode-execute?

Il PC contiene l'indirizzo della prossima istruzione, l'IR l'istruzione in esecuzione. Fetch: si copia in IR l'istruzione all'indirizzo del PC e si incrementa il PC; decode: la CU riconosce il codice operativo; execute: si esegue. Un salto scrive un nuovo indirizzo nel PC.

Differenza tra compilatore, linker e interprete?

Il compilatore traduce tutto il programma sorgente in codice oggetto (linguaggio macchina), segnalando gli errori; il linker unisce il codice oggetto con quello delle librerie e produce l'eseguibile. Un interprete invece traduce ed esegue un'istruzione alla volta, senza produrre un eseguibile.

Perché si usa il complemento a due?

Ha un solo zero, rappresenta [-2n-1, 2n-1-1], e la sottrazione diventa una somma (N - M = N + (-M)), quindi basta un solo circuito sommatore.

Perché i float sono approssimati? Cos'è l'eccesso 127?

I bit sono finiti (23 di mantissa) e molte frazioni in binario sono periodiche (0.1, 0.37...): le cifre in più si perdono. L'esponente è memorizzato sommandogli 127, così con 8 bit senza segno (0-255) si rappresentano esponenti anche negativi.

Linguaggio C

Cos'è un record di attivazione?

La zona di memoria (sulla pila) allocata a ogni chiamata di funzione: contiene parametri formali, variabili locali, valore e indirizzo di ritorno. Viene deallocata quando la funzione termina. Ogni chiamata ricorsiva ha il suo RDA.

Come si passano i parametri in C?

Sempre per valore: la funzione riceve una copia. Per modificare una variabile del chiamante si passa il suo indirizzo (parametro puntatore, "parametro di output"). Gli array sembrano passati per riferimento perché il loro nome è già l'indirizzo del primo elemento.

Differenza tra variabile locale, globale, static?

Locale: visibile nel blocco, vive durante l'attivazione. Globale: visibile ovunque dopo la dichiarazione, vive per tutto il programma. Locale static: visibile nella funzione ma conserva il valore tra le chiamate.

Che relazione c'è tra array e puntatori?

Il nome dell'array è l'indirizzo del primo elemento; v[i] equivale a *(v+i) (aritmetica dei puntatori: +1 avanza di un elemento, non di un byte). Ma un array non si può riassegnare né incrementare; un puntatore sì.

Cos'è una stringa in C? Perché `malloc(strlen(s)+1)`?

Un array di char terminato da '\0'. strlen conta i caratteri senza il terminatore, quindi serve un posto in più per il '\0'.

Differenza tra allocazione statica e dinamica?

Statica: dimensione decisa nel codice, memoria gestita automaticamente (variabili locali nella pila, globali). Dinamica: memoria chiesta durante l'esecuzione con malloc nello heap, della dimensione che serve; resta finché non si chiama free. Rischi: NULL non controllato, memory leak, puntatori pendenti.

Cosa sono le stringhe "esatte" e perché si usano?

Stringhe allocate dinamicamente con esattamente strlen + 1 caratteri: non si spreca memoria come con array sovradimensionati. Si legge in un buffer grande, si alloca la dimensione esatta, si copia.

Differenza tra file di testo e file binario?

Il file di testo contiene caratteri (leggibili, fprintf/fscanf); il binario contiene i byte come sono in memoria (fwrite/fread), è più compatto e permette l'accesso diretto con fseek a record di dimensione fissa.

Struct per valore o per indirizzo?

Per valore la funzione lavora su una copia (e copiare una struct grande costa); per indirizzo può modificare l'originale e si usa la freccia p->campo.

Metodologia e strutture dati

Cos'è la ricorsione? Cosa serve perché termini?

Una funzione che chiama se stessa. Servono un caso base risolto direttamente e un caso ricorsivo che si riduce a un problema più piccolo, avvicinandosi al caso base.

Ricorsione o iterazione?

Sono equivalenti in potenza. La ricorsione è più naturale per strutture ricorsive (liste, alberi) e per il divide et impera, ma costa un RDA per chiamata (tempo e memoria, rischio di stack overflow).

Come funzionano selection, bubble e insertion sort? Quanto costano?

Selection: cerca il minimo del resto e lo scambia in posizione. Bubble: confronta e scambia vicini, il più grande sale in fondo. Insertion: inserisce ogni elemento al suo posto nella parte ordinata. Tutti circa n² confronti nel caso peggiore; merge sort n log n.

Quando si può usare la ricerca binaria?

Solo su dati ordinati e con accesso diretto (array). Dimezza lo spazio di ricerca a ogni passo: circa log2 n confronti.

Scatola nera e scatola trasparente: differenze?

Nera: test scelti dalla specifica (classi di equivalenza dell'input, casi limite), senza guardare il codice. Trasparente: test scelti guardando il codice per coprire istruzioni, decisioni, condizioni, valori limite. Nessuno dei due garantisce l'assenza di errori.

Cos'è il test top-down? Cos'è uno stub?

Test incrementale di un programma modulare: si prova una funzione alla volta partendo dal main; le funzioni non ancora provate sono sostituite da stub (versioni finte che danno il risultato giusto per il test).

Cos'è un tipo di dato astratto?

Un tipo definito dalle operazioni che si possono fare sui dati e dal loro significato, indipendentemente dalla rappresentazione concreta (array, lista...). Esempi: tabella, lista.

Lista o array: vantaggi e svantaggi?

Lista: dimensione dinamica, inserimenti ed eliminazioni senza spostare elementi, nessuno spreco; ma niente accesso diretto (per il k-esimo bisogna scorrere) e un puntatore in più per nodo. Array: accesso diretto v[k], ricerca binaria possibile; ma dimensione fissa (o costose realloc) e spostamenti per inserire in mezzo.

Perché alcune funzioni sulle liste ricevono `TipoLista *`?

Perché possono cambiare la testa (inserimento in testa o ordinato, eliminazione del primo): per modificare il puntatore di testa del chiamante bisogna riceverne l'indirizzo.

Cos'è il record generatore?

Un nodo fittizio messo davanti al primo nodo vero: così ogni nodo ha un predecessore e gli inserimenti/eliminazioni non hanno il caso speciale della testa. Alla fine la testa è rg.next.

Cosa sono le visite di un albero?

Algoritmi ricorsivi che esaminano tutti i nodi: preordine (radice, sinistro, destro), inordine (sinistro, radice, destro), postordine (sinistro, destro, radice). In un albero binario di ricerca l'inordine dà i valori ordinati.

Capitolo 21

Palestra di programmazione

25 esercizi graduati, dal primo programma alle liste. Tutte le soluzioni sono programmi completi, compilati ed eseguiti. Come usarli:

  1. leggi il testo e scrivi la tua soluzione al computer (o su carta, dai livelli 6-7);
  2. compila e prova con l'esempio indicato e con altri dati scelti da te;
  3. solo dopo apri la soluzione e confrontala con la tua: ci sono tanti modi giusti di scrivere un programma, ma controlla di non aver dimenticato casi;
  4. dopo qualche giorno rifai gli esercizi in cui ti eri bloccato.

Livello 1: input, output, espressioni

Esercizio P01. Da Celsius a Fahrenheit

Leggi una temperatura in gradi Celsius (anche con decimali) e stampala in Fahrenheit: F = C × 9/5 + 32.

Soluzione

Input 36.6 → 36.6 C = 97.9 F. Attenzione: se c fosse int, c * 9 / 5 farebbe una divisione intera e perderebbe i decimali; e scrivere 9 / 5 * c darebbe sempre c (perché 9 / 5 vale 1).

Esercizio P02. Secondi in ore, minuti, secondi

Leggi un numero di secondi e stampalo come ore, minuti e secondi.

Soluzione

Input 3725 → 1 h 2 min 5 s. Divisione intera / e resto % sono la coppia perfetta per questi problemi.

Esercizio P03. Pari o dispari, positivo o negativo

Leggi un intero e di' se è pari o dispari, e se è positivo, negativo o zero.

Soluzione

Input -7 → -7 e dispari,ed enegativo. Nota la catena if / else if / else.

Esercizio P04. Equazione di secondo grado

Leggi a, b, c e stampa le soluzioni reali di ax² + bx + c = 0 (gestisci a = 0 e il discriminante negativo).

Soluzione

Input 1 -3 2 → x1 = 2.000 x2 = 1.000. Con gcc da terminale serve -lm per sqrt; Dev-C++ lo fa da solo.

Livello 2: cicli

Esercizio P05. Tabellina

Leggi n e stampa la sua tabellina da 1 a 10, ben incolonnata.

Soluzione

%2d e %3d riservano 2 o 3 spazi: le colonne restano allineate.

Esercizio P06. Somma e media di n numeri

Leggi quanti numeri verranno dati, poi leggili e stampa somma e media.

Soluzione

Input 3, poi 1.5 2.5 5 → somma 9.00, media 3.00. Schema accumulatore.

Esercizio P07. Massimo con sentinella

Leggi numeri positivi finché arriva 0; stampa quanti sono e il massimo.

Soluzione

Input 4 9 2 0 → letti 3 numeri, massimo 9. Schema sentinella + massimo (il candidato parte dal primo valore letto).

Esercizio P08. Cifre di un numero

Leggi un intero positivo; stampalo con le cifre al contrario e stampa la somma delle cifre.

Soluzione

Input 1234 → 4321, somma 10. n % 10 è l'ultima cifra, n / 10 la toglie.

Esercizio P09. Triangolo di asterischi

Leggi n e disegna un triangolo di n righe: la riga i ha i asterischi.

Soluzione

Due cicli annidati: quello esterno conta le righe, quello interno stampa gli asterischi della riga.

Esercizio P10. Numero perfetto

Un numero è perfetto se è uguale alla somma dei suoi divisori minori di lui (6 = 1+2+3). Verifica se n è perfetto.

Soluzione

Input 28 → perfetto (1+2+4+7+14).

Livello 3: funzioni

Esercizio P11. Funzione primo

Scrivi int primo(int n) e usala per stampare i primi in un intervallo [a, b].

Soluzione

Input 10 30 → 11 13 17 19 23 29. Il return 0 dentro il ciclo termina subito la funzione.

Esercizio P12. Fattoriale e coefficiente binomiale

Scrivi long fattoriale(int n) e usala per calcolare il coefficiente binomiale n! / (k!(n-k)!).

Soluzione

Input 5 2 → 5! = 120, binomiale 10. Una funzione usata per costruirne un'altra: riuso.

Esercizio P13. Calcolatrice con switch

Leggi operazioni come 3 * 4 finché arriva 0 x 0; una funzione calcola il risultato e segnala con un parametro di output le operazioni non valide (operatore sconosciuto, divisione per zero).

Soluzione

Input 3 * 4, 8 / 0, 9 - 2.5 → = 12, operazione non valida, = 6.5. Lo spazio in " %c" fa saltare gli spazi prima dell'operatore.

Livello 4: array

Esercizio P14. Al contrario

Leggi 5 interi in un array e stampali in ordine inverso.

Soluzione

Ricorda: gli indici vanno da 0 a N-1; il ciclo all'indietro parte da N - 1.

Esercizio P15. Quante volte compare

Dato un array, stampa per ogni valore distinto quante volte compare.

Soluzione

Trucco: stampo un valore solo se non compare prima della sua posizione (conta(v, i, v[i]) == 0), riusando la stessa funzione su una parte dell'array.

Esercizio P16. Togliere i doppioni

Da un array ordinato elimina i valori ripetuti, compattando; restituisci la nuova dimensione.

Soluzione

{1,1,2,4,4,4,7,9,9} → 1 2 4 7 9. Stessa idea di condensa (capitolo 6).

Esercizio P17. Matrice trasposta

Calcola la trasposta di una matrice 2×3 (le righe diventano colonne) e stampala.

Soluzione

Output: 1 4 / 2 5 / 3 6.

Livello 5: stringhe e puntatori

Esercizio P18. Maiuscolo e palindromo

Leggi una parola, trasformala in maiuscolo e di' se è palindroma (versione iterativa, con due indici).

Soluzione

Input Radar → RADAR e palindroma.%50s` impedisce di leggere più caratteri di quanti l'array ne contenga.

Esercizio P19. strcmp e strcpy fatte a mano

Scrivi le tue versioni di strcmp e strcpy.

Soluzione

Il cuore delle stringhe C: si scorre fino al '\0', che va sempre copiato.

Esercizio P20. Scambia minimo e massimo

Scrivi una funzione che scambia di posto minimo e massimo di un array e restituisce le loro posizioni con due parametri di output.

Soluzione

{5,9,1,7} → 5 1 9 7, min era in 2, max in 1.

Livello 6: struct, memoria dinamica, file

Esercizio P21. Classe dinamica

Leggi n, alloca dinamicamente un array di n studenti (nome come stringa esatta, voto), calcola la media e stampa chi sta sopra la media. Libera tutto alla fine.

Soluzione

Input 3, anna 28, luca 22, sara 30 → media 26.67, sopra: anna sara. Prima si liberano le stringhe, poi l'array.

Esercizio P22. Salva e ricarica

Salva un array di studenti su un file di testo e ricaricalo in un altro array.

Soluzione

Il ciclo di lettura si ferma quando fscanf non legge più 2 valori (o l'array è pieno).

Livello 7: liste

Esercizio P23. Costruisci una lista dall'input

Leggi interi fino allo 0 e costruisci una lista nello stesso ordine di input; stampala e deallocala.

Soluzione

Input 5 3 8 0 → 5 -> 3 -> 8 -> NULL. Tenere un puntatore all'ultimo nodo evita di riscorrere la lista a ogni inserimento.

Esercizio P24. Sopra la media

Conta i nodi di una lista con valore maggiore della media dei valori.

Soluzione

Servono due scansioni: la prima calcola la media, la seconda conta. Lista 2 8 5 9 1 → 2.

Esercizio P25. Dizionario ordinato (programma completo)

Programma con menu: aggiungi una parola (in ordine alfabetico, senza doppioni, come stringa esatta), elimina una parola, stampa il dizionario. Alla fine dealloca tutto.

Soluzione

È un piccolo "homework": tipi, inserimento ordinato con strcmp, eliminazione, stampa, deallocazione e un menu con switch. Se lo sai scrivere da solo, sei pronto per gli esercizi 1 e 2 dello scritto.
